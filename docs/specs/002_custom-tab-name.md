# 002: タブ名称のカスタマイズ機能 仕様書

## 概要
Markdown Concat Viewer の Webview タブ名称（タイトル）を、ユーザー設定（VS Code設定）でカスタマイズ可能にする。

## 目的
- 複数のディレクトリやファイルセットを同時に閲覧する際、タブ名で内容を識別しやすくする。
- デフォルトのタブ名（"Markdown Concat" など）では内容が判別しづらい問題を解消する。

## 機能要件
- タブ名称のフォーマットを設定で指定できること。
- 設定内で以下の変数をサポートすること。
  - `${rootName}`: 基点となるディレクトリ名、またはファイル名（複数選択時は代表名）。
  - `${fileCount}`: 連結された Markdown ファイルの総数。
- 設定変更時に、即座に開いているタブの名称へ反映されること（可能なら）。

## 設定仕様
- **設定キー**: `markdownConcatViewer.view.title`
- **型**: `string`
- **デフォルト値**: `"Concat Preview: ${rootName}"`
- **利用可能な変数**:
  - `${rootName}`
    - 単一ファイル選択時: そのファイル名（拡張子含む/含まないは実装依存だが、今回は拡張子含むファイル名を推奨）
    - ディレクトリ選択時: そのディレクトリ名
    - 複数選択時: 1つ目の要素の名前（または「〜等」などの表現、実装判断）
  - `${fileCount}`
    - 連結対象となったファイル数

## 実装方針
1. `package.json` の `contributes.configuration` に `markdownConcatViewer.view.title` を追加する。
2. Webview パネル生成時（`createWebviewPanel`）に、設定値を取得してタイトルを決定する。
3. タイトル文字列内の変数を置換するユーティリティ関数を実装する。
4. 設定変更監視（`onDidChangeConfiguration`）で、既存パネルのタイトルを更新する。

## 考慮事項
- 変数が解決できない場合の挙動: 空文字にするか、変数をそのまま残すか。→ そのまま残す（ユーザーがミスに気づきやすい）。
- `${rootName}` の解決ロジック詳細:
  - 既存の `rootPath` などを利用して解決する。

## テスト計画
- 設定変更でタイトルが変わること。
- 変数が正しく置換されること。
- デフォルト設定で違和感のないタイトルになること。
